# Labs data scripts

The data behind the AI engineering charts on labs.sammii.dev. Each script writes
the `data.json` its chart imports, so a chart can be regenerated by running its
script again. Only generated, aggregate data is committed; the corpora the
scripts read (other repositories, model files) stay where they are.

Python 3.11 or later, with `tiktoken` and `numpy` (`pip install tiktoken numpy`).
Everything runs offline.

## Tokenisers, offline (`tok.py`)

tiktoken downloads its BPE files on first use. To run without a network, put the
two files in a folder and point `TIKTOKEN_CACHE_DIR` at it, named by the SHA-1 of
their download URL (that is tiktoken's own cache layout):

```sh
mkdir -p ~/.cache/tiktoken-offline && cd ~/.cache/tiktoken-offline
for n in cl100k_base o200k_base; do
  cp /path/to/$n.tiktoken "$(printf 'https://openaipublic.blob.core.windows.net/encodings/%s.tiktoken' $n | shasum | cut -d' ' -f1)"
done
export TIKTOKEN_CACHE_DIR=~/.cache/tiktoken-offline
```

The copies used on 19 October 2026 came from the `gpt-tokenizer` npm package's
`data/` folder (version 3.4.0). tiktoken checks every file against the SHA-256
pinned in its source, so a wrong file fails to load rather than miscounting:
cl100k_base `223921b7…65b2a7`, o200k_base `446a9538…cfb1a2d`, both matched.

Llama 3 and Gemma 3 tokenisers are read from the header of a GGUF model file;
the first 40 MB of the file holds the whole vocabulary:

```sh
ssh mini 'head -c 40000000 ~/.ollama/models/blobs/sha256-<digest>' > hermes3-head.gguf
```

The digest is the `application/vnd.ollama.image.model` layer in
`~/.ollama/models/manifests/registry.ollama.ai/library/<model>/<tag>`.

## A context window, to scale (`context_window.py`)

```sh
python3 scripts/labs/context_window.py
```

Counts tokens in four of my repositories (`~/development/{quickcut,
sammii-hk.github.io,spellcast,lunary}`) and in my published blog posts with
o200k_base and cl100k_base. Files are read from git at each repo's
`origin/HEAD`, so local branches and uncommitted work do not count. Skipped:
dependency and build folders, lock files, generated files (named as generated,
or migration-tool snapshots), backups, minified bundles and source maps, images
including SVG, fonts, media, archives, anything with a NUL byte, and large
text files with almost no whitespace (base64 and minified data).

Only totals are written: files, bytes, and tokens split into code and
everything else, per repo. No file names, paths or code leave the script.

The page, short story and novel are word counts by definition times the
tokens per word measured on the prose of the blog (code blocks removed).

## Where an LLM call spends its time (`llm_latency.py`)

```sh
scp scripts/labs/llm_latency.py content/blog/31-vercel-crons-solo-product.md mini:/tmp/
ssh mini 'python3 /tmp/llm_latency.py measure --article /tmp/31-vercel-crons-solo-product.md' > runs.jsonl
python3 scripts/labs/llm_latency.py summarise runs.jsonl
```

The measure step uses only the standard library, so it runs on the Mac mini as
is. It streams chat calls to the local Ollama and timestamps the connection,
the request and every streamed chunk on the client; Ollama's final message adds
model load, prompt evaluation and generation. Each call is written as one JSON
line when it finishes. The model is `qwen3.5:2b` at the 4,096-token context it
is already served with, so the run never evicts another job's model on the
shared machine (a first attempt with `gemma3:4b-it-qat` did, and was stopped).
`--codex N` (at most 2) adds the same short prompt through the local Codex
proxy; on 19 October 2026 the proxy refused both calls with its usage hold, so
no hosted figures are in the chart.

`llm-runs-2026-10-19.jsonl` is the raw run behind the published chart (28
Ollama calls plus the two refused proxy calls), kept so the summary can be
re-derived. It contains timings and the model's own output, nothing else.

## Lunary's grimoire, mapped by meaning (`grimoire_map.py`)

```sh
ssh -N -L 11435:127.0.0.1:11434 mini &
python3 scripts/labs/grimoire_map.py --ollama http://127.0.0.1:11435
```

No database: everything comes from the lunary repository at `origin/main`
through `git show`. The article list is the grimoire search index; each
article's text is its title, summary and keywords plus its body fields where
the repo holds them as data (crystals, spells, tarot, runes, angel numbers,
life path numbers, chakras, correspondences). Embeddings are
`qwen3-embedding:0.6b` on the Mac mini's Ollama (1,024 dimensions, cached to
`$TMPDIR/grimoire-embeddings.npy` between runs). Layout: L2-normalise, PCA to
50 dimensions, exact t-SNE (perplexity 30, 1,000 iterations, PCA start,
seed 42) in NumPy. Neighbours are cosine similarity in the full 1,024
dimensions: ten for obsidian, five for every other article.

The JSON holds title, slug, category, x, y, whether the article had a body,
and neighbour indices. Article text and vectors are not committed.

## How text becomes tokens (`tokens.py`)

```sh
python3 scripts/labs/tokens.py --llama hermes3-head.gguf --gemma gemma3-head.gguf [--verify http://127.0.0.1:11435]
```

Runs the chart's sentences through cl100k_base, o200k_base, Llama 3 and
Gemma 3 (see `tok.py`) and writes every token's id and exact text, or its
bytes in hex when a token is only part of a character. The script asserts
that each tokeniser's pieces join back into the input byte for byte.
`--verify` compares our Llama 3 and Gemma 3 counts with the prompt token
counts Ollama reports for `hermes3:8b` and `gemma3:4b-it-qat`; it loads both
models, so on the shared Mac mini run it when nothing else needs the memory.
